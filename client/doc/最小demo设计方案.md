《炸弹人：搜打撤》Demo 功能开发任务书

适用对象：AI 开发助手
技术栈：前端 Godot 4.X (GDScript)，后端 Go (建议 WebSocket 库：gorilla/websocket 或 nhooyr.io/websocket)
前提条件：地图已能正常生成，具备基础的场景显示能力。
1. Demo 总目标

完成一个 2~4 人联机、可对战、可搜刮、可撤离 的最小炸弹人玩法闭环。
一局时长：5 分钟。
撤离点规则：3 分钟激活，5 分钟强制结束。
2. 后端 (Go) 核心任务
2.1 数据结构定义

请用 Go struct 定义以下核心对象：

	GameMap：包含地图宽高，二维数组表示每个格子类型（不可破坏墙、可破坏墙、空地）。

	Player：ID、昵称、位置 (X, Y)、炸弹数量上限、当前炸弹数、威力范围、移动速度、是否有护盾。

	Bomb：ID、所属玩家、位置 (X, Y)、放置时间、威力（爆炸时从玩家属性中取）。

	Room：房间码、房主 ID、玩家列表、游戏状态（等待中/游戏中/结算）、当前 GameMap、开始时间。

2.2 房间管理

	创建房间：生成 4 位数字房间码，房主进入等待状态。

	加入房间：根据房间码加入，人数 2~4 人。

	房主在人数 >= 2 时可点击“开始游戏”。后端收到指令后：

		初始化 GameMap（单张固定地图或调用已有生成逻辑）。

		将玩家位置分配到四个角落出生点。

		广播 game_start 消息给房间内所有客户端，并携带地图数据和玩家初始属性。

		开始游戏主循环（建议帧率 20 tick/s）。

2.3 游戏主循环与核心判定（必须服务端权威）

每一 Tick 处理客户端发来的操作指令队列：

	移动：校验目标格是否在合理范围（一次一格）、是否可通行（不能穿墙/穿炸弹/穿玩家）。更新位置，广播 player_move。

	放置炸弹：校验玩家当前持有炸弹数是否小于上限，目标格是否已有炸弹。放置后扣除持有数，广播 bomb_placed，记录放置时间。

	炸弹爆炸：遍历所有场上炸弹，若 当前时间 - 放置时间 >= 2秒，立即爆炸：

		计算十字爆炸范围，遇到不可破坏墙停止。

		摧毁范围内的可破坏墙，广播 wall_destroyed。

		对范围内所有玩家造成伤害（先判断护盾，有则消耗护盾并向该玩家私发 shield_consumed；无则判定死亡，广播 player_dead，移除玩家，掉落其拾获道具于原地）。

		对范围内的其他炸弹，连锁引爆（立即触发其爆炸，递归处理）。

		范围内可破坏墙被摧毁时，30% 概率生成随机道具，广播 item_spawn。

道具拾取：

	客户端发送 pick_item，后端验证玩家坐标与道具坐标重合，拾取后广播 item_picked，并更新玩家属性，将该道具的效果即时应用在服务端玩家数据上。

2.4 撤离点系统

	游戏第 3 分钟，后端激活撤离点（地图中心特定格子）。

	客户端发送 evacuate，后端验证玩家是否在撤离点坐标：

		开始 2 秒倒计时。期间若该玩家受到任何伤害/移动/放炸弹，立即中断。

		倒计时结束，判定撤离成功：广播 player_evacuated，该玩家标记为“撤离成功，保留物品”，离开地图。

	游戏第 5 分钟，后端强制结束，所有未撤离且未死亡的玩家视为“撤离失败，物品全丢”。

2.5 通信协议设计

建议使用 JSON 格式的 WebSocket 消息，统一格式：
json

{
  "type": "game_over",
  "payload": { ... }
}

部分关键消息类型：

	客户端→服务端：join_room, create_room, start_game, player_move, place_bomb, pick_item, evacuate。

	服务端→客户端：room_joined, game_start, player_move, bomb_placed, wall_destroyed, item_spawn, item_picked, player_dead, player_evacuated, game_over, error。

game_start 的 payload 必须包含：完整地图二维数组、所有玩家初始状态、撤离点倒计时等全局参数。
game_over 的 payload 包含每个玩家的结果（撤离成功/失败/死亡）及结算摘要。
3. 前端 (Godot) 核心任务
3.1 全局架构

	使用一个 NetworkManager 单例管理 WebSocket 连接、收发消息、派发信号。

	场景划分：

		MainMenu（昵称输入、创建/加入房间）。

		RoomLobby（显示房号、玩家列表、开始按钮[仅房主]）。

		GameScene（战斗主场景，仅有这一份地图实例）。

3.2 主界面与房间

	MainMenu：连接服务器后，输入昵称，调用 create_room 或 join_room。

	RoomLobby：收到 room_joined 后进入，显示当前房间内所有玩家。当自己是房主且人数 >=2 时，“开始游戏”按钮可用。按下后发送 start_game。收到 game_start 后，场景切换到 GameScene，并根据后端传来的地图数据构建地图。

3.3 地图渲染与玩家控制

你已有地图，这里补充一下玩家和炸弹的表现需求：

	地图层：根据 GameStart 中的二维数组，实例化不可破坏墙、可破坏墙的 Tile。

	玩家角色：用不同颜色的简单图形或 Sprite 区分。移动时做网格间平滑插值移动（0.2 秒过渡），或者瞬移一格（由表现决定）。

	输入处理：

		方向键按下时，向服务器发送 player_move 消息（包含方向）。

		空格键发送 place_bomb。

		移动到道具上自动发送 pick_item。

		在撤离点上按交互键（如 E）发送 evacuate。

3.4 视觉反馈与状态同步

	监听 bomb_placed，在对应格子创建炸弹节点，并播放 2 秒倒计时闪烁动画。

	监听 wall_destroyed，移除对应可破坏墙节点，播放破碎粒子。

	监听 item_spawn 和 item_picked，动态生成/删除道具图标。

	监听 player_dead，玩家角色播放死亡动画并消失（可原地留下一个墓碑 Sprite）。

	监听 player_evacuated，角色播放传送特效并消失。

	护盾存在时，给玩家身上绘制一层持续光圈（监听属性变化或服务端单独推送）。

3.5 UI 与 HUD

	左上角显示本局剩余时间（5分钟倒计时）。

	右上角显示当前自身属性：炸弹数量/上限、威力、是否有护盾（图标）。

	撤离点激活时（3分钟），在撤离点格子显示明显光柱或标记。

	撤离读条时，玩家头顶显示“撤离中 2s...”进度条。

3.6 结算流程

	当收到 game_over 消息，展示一个结算面板：

		列出所有玩家及结果（“撤离成功，保留物品” / “撤离失败/死亡，物品丢失”）。

		有一个“返回房间”按钮，点击后回到 RoomLobby。

4. 给 AI 开发的拆解指令（可直接复制使用）

如果你将本任务书交给 AI，建议按以下顺序要求它逐模块生成代码：

	后端：生成 Go 项目基础与 WebSocket 框架

		给出 main.go，实现基本的 WebSocket 升级、客户端管理、房间路由。

	后端：房间管理、游戏启动与地图数据同步

		实现房间创建/加入、game_start 消息组装与广播。

	后端：游戏主循环、移动与放置炸弹校验

		实现 ticker，处理 player_move、place_bomb，以及服务端权威的位置记录。

	后端：爆炸逻辑、伤害、道具掉落与拾取

		实现十字爆炸、可破坏墙摧毁与 30% 掉落、护盾判定、连锁爆炸。

	后端：撤离点激活、撤离读条与游戏结束结算

		实现 3 分钟激活计时器，撤离倒计时中断逻辑，5 分钟强制结束并发送 game_over。

	前端：Godot 网络管理器与主菜单、房间场景

		提供 NetworkManager 脚本，MainMenu 和 RoomLobby 场景的基础 UI 与信号交互。

	前端：战斗场景地图构建与玩家控制

		根据已有地图生成逻辑，实例化 Tile，实现玩家输入与消息发送。

	前端：所有视觉反馈与 UI/HUD 实现

		包括炸弹动画、道具显示、状态 HUD、撤离读条、结算面板。
