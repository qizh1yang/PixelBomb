# PixelBomb 项目代码规范 (Godot 4)

## 1. 核心准则
1. **模块化资源邻近**：脚本、场景、私有资源必须放在同一个文件夹内。
2. **服务端权威**：所有关键逻辑（位移、伤害、掉落）必须由服务端判定。
3. **语言规范（强制）**：项目中的**一切文字信息**（UI 文本、游戏内提示、按钮、标签、弹窗、错误提示、结算信息等）**必须使用中文**，严禁出现英文展示文本。代码注释、变量命名、函数命名等技术标识符不受此限制。

## 2. 目录结构
```text
res://
├─ prefabs/      # 模块化预制件
├─ scenes/       # 流程场景
├─ scripts/      # 全局脚本
└─ assets/       # 公共资源
```

## 3. 命名规范
- **文件夹**：大驼峰 (PascalCase)
- **场景/脚本**：小写下划线 (snake_case)，且必须同名。
- **变量**：小驼峰 (smallCamelCase)，且强制要求类型注解。
- **函数**：小驼峰 (smallCamelCase)，且强制要求返回值类型。

## 4. 测试与调试 (Testing & Debugging)
### 4.1 测试入口 (Test Entry)
- **全局透明触发按钮**：位于屏幕正上方中央的透明区域，点击后展开 `DevHUD`。
- **动态测试面板**：根据当前场景自动生成对应的功能按钮。

### 4.2 场景化测试支持
- **登录场景**：提供 Mock Login 按钮，跳过服务器验证直接进入大厅。

## 5. 维护与重构规范 (Maintenance & Refactoring)
1. **禁止无故删减**：严禁在未得到明确指令的情况下移除已有功能。除非是经过验证的更优重构，否则必须保留原有逻辑的连续性。
2. **低耦合设计**：模块间通过信号 (Signals) 或通用接口交互。严禁在非必要情况下进行硬编码跨路径引用，确保组件可独立运作。
3. **功能完整性自检**：重构或大规模修改代码后，必须确认原有核心功能（如 UI 拖拽、坐标对齐、窗口同步逻辑）依然完备。
4. **强制中文注释**：所有具有核心功能的函数及复杂代码块，必须使用**中文**编写注释，阐明其设计意图、逻辑流向及作用。
- **游戏场景**：提供强制激活撤离点、自杀、填充背包等快捷功能。

### 4.3 离线支持 (Offline Support)
- 所有功能应能在 `is_offline_mode` 下正常预览 UI 和基础逻辑。
