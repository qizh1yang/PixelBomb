## Godot 场景文件解析错误修复（2026-05-06 第三次）

### 错误原因诊断

| 文件 | 错误 | 根因 |
|---|---|---|
| player2.tscn, bomb.tscn, explosion_effect.tscn | Parse Error: Expected '[' at line 1 | 上次 PowerShell WriteAllText 写入时带了 UTF-8 BOM（EF BB BF），Godot 不支持 BOM |
| ui/login/login.tscn:36 | Parse Error | 第36行 `StyleBoxFlat new()` 是非法内联写法，且文件头 UID `uid://loginc123` 格式非法 |
| roglaik.tscn UID 警告 | invalid UID: uid://cqw7qxycgnqwc 等 | .uid 文件内容与 tscn 中引用的 uid 值不一致（某次重新生成了 .uid 文件） |
| uid://7g21c5xl8pnx Unrecognized | 非阻塞警告 | uid_cache.bin 未收录新路径，Godot 会自动重建，已降级用 path 查找，功能正常 |

### 修复操作
1. **去掉 BOM**：player2.tscn、bomb.tscn、explosion_effect.tscn 用 ReadAllBytes/WriteAllBytes 去掉前3字节 EF BB BF
2. **修复 login.tscn**：
   - 头部 UID 改为合法值 `uid://e92383247617`，load_steps 从 2 改为 3
   - 添加 `[sub_resource type="StyleBoxFlat" id="StyleBoxFlat_panel"]` 定义块
   - 第36行改为 `SubResource("StyleBoxFlat_panel")`
3. **修复 roglaik.tscn UID**：将3个脚本的 uid 引用更新为 .uid 文件中的实际值
   - roglaik.gd: `uid://cqw7qxycgnqwc` → `uid://b64p6ytw00qrs`
   - floor_layer.gd: `uid://dubidsyh57xhb` → `uid://daaqtur6lt37r`
   - wall_layer.gd: `uid://dwav45ya8exxn` → `uid://7ajria1q45uc`

### 经验教训
- **PowerShell 写 tscn 文件必须用 WriteAllBytes**，不能用 WriteAllText（会加 BOM）
- Godot tscn 不允许 `ClassName new()` 内联写法，必须先声明 `[sub_resource]` 再引用
- Godot UID 格式必须是随机的字母数字串，不能手写语义化值如 `uid://loginc123`

### 文件夹重命名 levels/ → map/
- 外层 `levels/` → `map/`，子文件夹 `roglaik/` → `map_classic/`
